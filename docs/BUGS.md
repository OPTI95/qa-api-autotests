# Найденные дефекты

Расхождения между [официальной спецификацией](https://petstore.swagger.io/v2/swagger.json)
Swagger Petstore и фактическим поведением сервиса. Каждый дефект закрыт автотестом
с `@pytest.mark.xfail(strict=True)`: тест падает, если баг починят, — значит
документация здесь не разъезжается с кодом.

---

## BUG-001 — Питомец создаётся без обязательного поля `name`

| | |
|---|---|
| **Severity** | Major |
| **Priority** | Medium |
| **Компонент** | `POST /pet` |
| **Тест** | `test_pet_without_required_name_rejected` |

**Предусловия:** сервис доступен по `https://petstore.swagger.io/v2`.

**Шаги воспроизведения:**
1. Отправить `POST /pet` с телом `{"id": 91234567, "photoUrls": []}`.

**Ожидаемый результат:** `400 Bad Request` — в `swagger.json` поле `name`
описано в блоке `required` схемы `Pet`.

**Фактический результат:** `200 OK`, объект создан с `name = null`.

**Влияние:** в хранилище появляются записи без имени; клиенты, полагающиеся
на контракт, получают `null` в обязательном поле и падают при отображении.

## BUG-002 — Полностью пустое тело запроса принимается

| | |
|---|---|
| **Severity** | Major |
| **Priority** | Medium |
| **Компонент** | `POST /pet` |
| **Тест** | `test_empty_payload_rejected` |

**Шаги воспроизведения:**
1. Отправить `POST /pet` с телом `{}`.

**Ожидаемый результат:** `400 Bad Request`, ни одно обязательное поле не передано.

**Фактический результат:** `200 OK`, создаётся пустая запись.

**Влияние:** база засоряется пустыми объектами; отсутствует валидация входных
данных на уровне API, что перекладывает проверку на каждого клиента.

## BUG-003 — `findByStatus` принимает несуществующий статус

| | |
|---|---|
| **Severity** | Minor |
| **Priority** | Low |
| **Компонент** | `GET /pet/findByStatus` |
| **Тест** | `test_invalid_status_rejected` |

**Шаги воспроизведения:**
1. Выполнить `GET /pet/findByStatus?status=bogus-status`.

**Ожидаемый результат:** `400 Invalid status value` — ответ описан
в спецификации; допустимы только `available`, `pending`, `sold`.

**Фактический результат:** `200 OK` с пустым либо произвольным списком.

**Влияние:** опечатка в параметре не диагностируется — клиент получает пустую
выдачу вместо явной ошибки и трактует её как «питомцев нет».
